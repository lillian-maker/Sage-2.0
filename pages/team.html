WHAT MAKES AN AI EMPLOYEE PROFESSIONAL

专业性，落实在判断的方法与标准里

Agent、Skills 与 MCP 是实现手段。对业务而言，更重要的是它们支持什么判断、留下什么依据。

01 / AGENT

职责决定问题的问法

专业岗位不仅有角色名称，还要明确要解决的决策、允许使用的资料、必须检查的约束与交付标准。机会研究先问证据是否成立；商业判断再问成立后是否值得投入。

同一个模型可以承担不同岗位，但岗位身份本身不证明专业能力。能力要在具体任务中接受验收。

02 / SKILLS

方法不能只靠临场发挥

Skills 将可复用的分析步骤、判断规则和成果要求交给岗位。VOC 研究不能只归类情绪，还应核对样本、需求频次、现有替代方案与反证；经营分析不能只读增长率，还应核对口径与约束。

方法需要版本、适用条件和测试样本。更新一段提示词，不等于改善了业务判断。

03 / CONTEXT

先理解这家企业，再讨论行业经验

品牌定位、目标市场、渠道、商品结构、资金约束与历史决策共同构成业务上下文。通用行业知识无法替代这些条件；同一建议，对不同品牌可能有相反的结果。

共享上下文要保留资料来源、时间和权限，并把事实、推断与缺失信息分开，避免把过期经验当成当前事实。

04 / MCP

工具提供依据，而不是授予权力

MCP 用于规范工具与数据连接。查询记录、执行计算、检索资料，让判断能够接触可核对的业务依据，而不是仅依赖模型记忆。

连接成功不代表数据准确，也不代表可以改价、采购或发布。访问权限、执行授权与真实结果必须分别确认。

05 / HANDOFF

交接的是可使用的成果

研究岗位不能只交一份长报告。下一岗位需要知道：证据来自哪里，覆盖什么范围，哪些假设未验证，什么条件下才能继续决策。

交接标准决定成果能否被复用。清晰的来源、约束与未决问题，比更多聊天记录更重要。

06 / REVIEW

复核需要不同的检查职责

让另一个 AI 重复问同一个问题，并不等于独立复核。复核岗位应检查来源、计算、遗漏条件、反例和授权范围，并有能力提出退回或需要补证。

多岗位也可能共享同一种偏差。重要结论仍需外部证据、确定性校验和人工判断共同支持。

07 / CONTROL

判断与业务执行不是同一权限

提出方案、批准方案、执行动作和确认完成，分别承担不同责任。涉及资金、公开发布或外部系统变更时，应明确负责人、预算和可撤回条件。

AI 的建议不能代替企业授权；工具返回成功，也不能直接证明经营目标已经实现。

08 / EVALUATION

专业能力必须能被反复检验

任务验收应覆盖事实正确性、计算口径、证据充分性、约束遵守与交接可用性。版本变化后，需要在相同任务上比较，不能用一次顺利演示证明稳定。

评估结果支持方法改进，不支持“绝不出错”或“保证增长”的承诺。

COLLABORATION WITH A REASON

团队的意义，不是意见更多
而是让判断经得起不同专业的追问

需要协作的，是相互影响的判断

当需求证据、产品可行性、利润条件与进入风险相互牵制时，分专业研究能保持各自的检查深度。汇总时不应抹平分歧，而应指出结论依赖哪些条件、缺什么证据、由谁确认。

岗位按问题组织，不是让全部员工同时运行。研究可以并行，依赖同一结论的工作则需要明确接收条件。

不需要团队的，保持简单

明确的字段校验、计算、单次检索或短文案任务，可以用规则、工具或单个岗位完成。只有增加协作能够改善覆盖范围、复核质量或交接可靠性时，才值得承担额外耗时与 Sage Credits 消耗。

团队数量不等于结果质量。Sage 的组织设计应服务于任务，而不是为了展示更多 Agent。

JUDGE THE WORK, NOT THE PERSONA

如何判断 AI 团队真的帮上了忙

不要只看报告是否完整，要看它是否支持下一项真实决策。

依据可核对
关键结论能找到来源、时间、计算口径与适用范围；不能确认的信息明确保留。
取舍说得清
不只提出一个建议，也说明备选方案、约束条件、潜在影响与尚未解决的分歧。
成果能接手
下一位负责人知道需要验证什么、谁来确认、接收什么成果，而不需要重新研究全部背景。
边界不混淆
分析完成、方案批准、执行完成与经营改善分别有证据，不用一份报告替代业务结果。
