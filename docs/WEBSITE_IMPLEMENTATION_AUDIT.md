## 后端实际能力与缺口

### 账户与个人设置

邮箱OTP已有有效期、错误次数、Session绑定、一次性消费、IP/身份限流、摘要存储及SMTP发送代码。配置未就绪会503，手机号登录始终关闭，不能把手机号输入UI视作短信实现。会话、当前计费账户切换、CSRF退出已有接口。

个人设置目前只读；会话返回 `display_name=''`，无资料更新路由。现有页面不能支撑用户设置自己的显示名。共享退出POST后重新读取会话确认已经实现，但跨标签、页面恢复与真实服务联调仍需专项验收。

证据：`backend/views.py:109-136,156-240,289-302,321-354`；`src/pages/site-shell.js:20-46`。

### 咨询与预约

官网表单字段为公司、手机号、选填邮箱、问题描述，首页和弹窗都阻止提交，不发送或保存。

后端已有 `billing/purchase-inquiries`，但面向已登录owner/billing_admin，字段是company、seats、requirements、contact_email，并非官网咨询契约。不能直接将匿名四字段表单接到该接口，也不能说完全没有任何询单能力。已有采购询单包含限流、10分钟相同输入去重及审计，可参考并复用已存在的工具函数，不先加Service/Manager层。

缺少公开咨询接收、受权销售查看/处理、明确责任人和通知；“提交预约”应表示提交咨询请求，不应伪造已约定日期或销售已联系。

证据：`src/app.js:52`；`src/pages/site-shell.js:69-74`；`backend/views.py:249-283,289-302`。

### 免费体验和真实任务

已有资格/原任务/报告持久化内核、同用户任务幂等与完成后消费资格。当前公共API只有GET trial；内部start/event函数不是任务执行器，没有网页抓取与公开完成。示例和哈希不能替代真实报告质量验证。

官网开发必须覆盖启动、进度、刷新恢复、失败、报告阅读下载和一次体验资格闭环；执行器所需输入、数据授权、模型/工具边界须先确认。接收Shopify链接时，现有语法检查不足以替代网络层SSRF、DNS、重定向与内网地址隔离。

证据：`backend/trials.py:19-44,77-151`；`backend/views.py:298,333-337`；`src/pages/experience.js:59-61,181-229`。

### 账务非支付部分

已存在批准商品目录、报价/条款、幂等建单/恢复、订单与订阅、站内通知、Credits流水、企业成员/席位只读和内部额度预占/结算/释放。不是全静态，也不是已可售。企业编辑、发票、部分订阅变更能力关闭；跨期任务结算主动拒绝未定规则。真实渠道、扣款、退款、自动扣款本次不列开发项。

本轮只保留正式商品内容、权限、账户隔离、读取与用户反馈验收；不借此次官网计划改变原D01-D16商业门禁，也不把财务历史计划重复勾为已完成。

证据：`backend/views.py:355-469`；`backend/commerce/billing.py:973-1060`；`backend/commerce/subscriptions.py:436-491,1023,1163-1179`。

### 发布与全站质量

已存在Django生产安全配置、Host约束、secure cookie、CSRF/HTTPS/HSTS、live/ready、request_id与失败响应；没有本次公网账户API验收。生产明确禁止Django本地静态服务，须部署同源静态/API、正式进程及持久化PostgreSQL，不能公网暴露runserver。

生产代理下OTP读取REMOTE_ADDR，必须按实际代理链确定可信客户端来源，否则可能共用限流；不得直接盲信外部X-Forwarded-For。readiness只证明库与迁移，不证明邮件/执行端。

中文/英文三页不等价：`build.py:35-40`保留旧英文team/enterprise/docs，旧英文导航登录链接也未匹配共享账户入口选择器。当前无统一canonical/hreflang/OG；部分页无description；文档失效地址无明确404策略。SEO和分享meta需在正式域名确定后输出，预览与账户页面单独定索引策略。

证据：`backend/settings.py:9-88`、`backend/apps.py:8-34`、`backend/views.py:34-55,171,508-519`、`build.py:35-40`、`src/pages/site-shell.js:8`。

## 四、实现原则与现有能力复用

沿用静态HTML/CSS/JS构建 + Django 5.2 LTS + PostgreSQL，不迁移框架、不新增应用平台。优先修改现有模型/路由/脚本和测试，不增加Manager/Service/Factory等抽象。只有独立真实数据生命周期才加小模型；沿用当前User，避免开发中更换AUTH_USER_MODEL。

- OTP复用LoginChallenge、AuthThrottle、LoginIdentity与现有验证流程；确需新增的“删除账号验证”必须明确purpose并绑定当前用户，登录码不得被通用验证端点误用于删除。
- Session复用Django服务端会话；仅增加用户可查询的会话元数据与撤销关联，不遍历解析所有用户Session来拼列表。不把原始session key暴露给客户端。
- 资料优先复用现有User名称字段；头像路径、推广偏好和注销状态以最小增量落库，不复制用户身份表。
- 官网匿名咨询不能强塞进当前PurchaseInquiry：该模型必有account/created_by/seats/邮箱，与访客表单不一致。保留既有采购询单和权限，新增最小咨询记录/处理历史，复用校验和限流工具。
- 销售后台首选Django自带admin的窄权限页面，不另建CRM。当前INSTALLED_APPS未启用admin，必须实施后再宣称有后台；启用admin需要完整权限、CSRF、登录和静态资源配置，不能公开内部财务模型。
- 用量现有my-usage主要表示席位/共享额度限制，不是完整本人任务流水；保留其能力，真实任务明细未来接执行记录。当前示例由只读展示数据生成，不新建模拟账务表。
- 账单/订单/流水直接复用现有接口；推广通知偏好与账务事件记录不同，不能关掉偏好就停止保存账务审计。

## 七、数据、权限和回滚门禁

拟新增资料/会话/咨询/偏好/删除相关迁移，开发前再次评估最小schema。本期计划不操作数据库。

权限边界：本人只管理本人资料/会话；销售权限不等于计费owner；企业资金/用量汇总依现有受权规则。匿名咨询仅能提交，不能查询别人记录。审核/角色不能由前端字段决定。所有敏感写CSRF保护与服务端鉴权，缓存no-store；头像展示路径安全，业务PII不出现在静态分享包。

完成后90天清除是已批准咨询规则，未完成咨询的最长保留期、备份到期、账号删除后必要账务保留细则仍待正式政策，不自行扩大90天到全部数据。备份恢复不得复活已撤销会话或已清除PII，恢复后二次清理和停用事实需验证。业务删除不是普通DB硬删；保留的PROTECT关系不等于继续可登录。

代码回退只能回退兼容代码，不能把已删除/停用身份恢复活跃。新敏感数据迁移若需撤回，先保留可审计快照并受权限保护；仅空测试库迁移往返不算生产回滚验证。没有生产操作授权时只交付脚本/步骤，不执行。
