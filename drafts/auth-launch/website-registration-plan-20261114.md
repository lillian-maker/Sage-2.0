# Sage 官网真人注册与登录实施计划

**目标：**在已发布的 `sagegogo.com` 上，让真人能够安全完成邮箱注册、退出、密码登录与找回密码，并以实际收件、会话与安全行为作为验收证据。

**方案：**复用现有 Django 认证流程、腾讯验证码及广州邮件推送模板；先只读核对目标环境并准备可回滚的受限联调，再完成协议审核与真实端到端验收，最后单独批准公开注册。Google 和手机号登录作为后续独立阶段，不阻塞邮箱首期。

**技术栈：**现有 Django、PostgreSQL、Docker Compose、腾讯云邮件推送 SES 与验证码，前端使用现有 `src/pages/auth.js`。

**依据：**[注册与协议审阅稿](review.md)、[受限部署候选与回滚清单](../restricted-deploy/README.md)、[项目开发记录](../../docs/BILLING_DEVELOPMENT.md)。官方参照：[Django 部署检查](https://docs.djangoproject.com/en/5.2/howto/deployment/checklist/)、[腾讯云验证码接入问题](https://cloud.tencent.com/document/product/1110/36828)、[腾讯云邮件推送普通发送](https://cloud.tencent.com/document/product/1288/74737)。

- [ ] 审阅真实验收结果、协议批准、部署/回滚与监控；明确公开范围与变更窗口，再按批准逐项启用必要开关。
- [ ] 公开后只用受控账号进行一次真实回归，检查注册、登录、找回与服务健康；监控错误和退信，出现阻断时停止新增注册并按已验证方案回退。
- [ ] 另行推进 Google：核对项目、OAuth 客户端、准确 HTTPS 回调、品牌与隐私审核，验收新用户、绑定和取消等分支。
- [ ] 另行推进手机：核对短信资质、签名、各用途模板与真实送达；不要使用其他用途模板替代。

**最终完成标准：**已发布网站上真人能够注册、登录并找回密码；邮箱实收、CAPTCHA 服务端校验、会话撤销、协议同意及安全回滚均有真实证据。任一关键步骤未测或仅有模拟结果，保持“未完成”。
