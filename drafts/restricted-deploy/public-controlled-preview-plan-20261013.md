# Sage 公网受控内测 Implementation Plan

> 2026-10-15接续：本文件的systemd/旧库部署架构已由[独立Docker执行方案](docker-deployment-acceptance-plan-20261015.md)替代，不按下方历史Architecture变更旧Sage。新三容器回环验收及入口安全轮换已通过；用户确认ICP备案未完成，最新备案办理清单见当前方案Task6。公网仍关闭，后续放行另批确认。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本项目不创建 worktree、不自动 commit/push；每个批次按下方权限边界执行，不把计划当作全部外部操作的授权。

**Goal:** 在满足上海节点域名网站接入条件后，使指定 Mac 可经公网 `https://sagegogo.com` 验收固定版本的 Sage；其他来源不能访问，SSH、数据库及应用内部端口保持隔离。

**Architecture:** 复用 BoBo、既有独立 Sage Nginx、Gunicorn 和 `sage_staging`，不引入 Tailscale 商业套餐、CDN、WAF 或新隧道。安全组仅放行准确来源 IPv4 /32 的 TCP 443；建议Nginx同时要求来源限制、HTTPS入口口令和精确Host，不把共享代理IP当设备身份。Gunicorn仍仅127.0.0.1:8000，PostgreSQL仍仅Unix socket；保留127.0.0.1:8443作为服务器内诊断入口。入口口令方案须用户确认并亲自配置凭据，不能与Sage真实账户登录混为一谈。

**Tech Stack:** Tencent CVM/安全组/TAT、TencentOS 4、Nginx、systemd、Gunicorn、Django 5.2、PostgreSQL 16、现有Python静态构建与Node验收工具。

**Spec:** 用户2026-10-13确认改走公网受控内测、停止推进付费Tailscale，并澄清“审核通过”仅指域名实名或SSL；`../../docs/BILLING_DEVELOPMENT.md`最新部署记录及七阶段商业上线总计划；`README.md`现有部署约束；`../auth-launch/review.md`认证材料与法律/供应商门禁。

## 1. 当前事实、假设和范围

### 已确认事实

- 用户已选择公网受控内测，不购买/开通Tailscale套餐。此决定不是允许向所有IP开放，也不是正式接收商业客户。
- 用户明确回答域名只完成实名或SSL审核，不能据此声明ICP已通过。上海节点的域名网站开放条件尚未满足已验证门禁。
- 本地源码与现有文档有大量已存在未提交变更；不是仅按Git HEAD就能复建当前功能。
- 10月12日部署记录：云端固定候选摘要前缀84d27f0435cc；本机HTTPS验证149个资源、14类检查及TLS1.2/1.3通过；网站只绑定回环，默认Nginx未启动。它不是10月13日最新源码已部署的证明。
- 10月13日实测：Tailscale只有这台Mac，没有BoBo；本机DNS接管=false。停止付费路线不会自动卸载客户端、恢复DNS或变更代理。
- `src/pages/site-shell.js`会调用`/api/auth/session`；`backend/views.py::session_data`可写入匿名会话的login_binding。浏览器浏览不是天然零数据库写入。

### 执行前必须新鲜核实

- BoBo实例、公网地址、安全组关联/优先级及IPv4/IPv6规则；旧记录不能替代现状。
- 独立新TAT连接、应用/Nginx/PG状态、实际监听、current指向及配置权限。
- TLS证书链/域名/有效期、ICP备案和腾讯云接入状态、现有DNS记录。
- Mac实际到站点的出口地址、未授权的独立测试出口；不能把代理界面节点名当出口证据。
- 新候选与云端版本的差异、实际迁移计划、配置门禁、可用备份和恢复证据。

### 本期边界

- 第一阶段仅批准来源及持有入口凭证的测试者访问；目标测试端为指定Mac。IP白名单本身不能证明硬件身份，特别是共享代理/NAT出口；不做全网开放、不新增任意其他测试人员。
- 初始验收以页面、静态资源、HTTPS和关闭门禁为主；允许的匿名测试会话在执行批次中明确列出，不创建真实业务账户、不导入真实客户数据。
- 真实注册、CAPTCHA、SES、Google、SMS、账号实际删除、支付、任务执行各自单独通过门禁后才开展受控联调。
- 全部真实支付和两个真实场景仍属于已确认商业上线P0；本计划只是改变阶段2的访问通道，不删除或降级七阶段总目标。
- 本轮只交付计划和追加索引/记录；不安装新组件、不改服务器、DNS、安全组或本机网络。

### G4：精确公网配置与离线安全验收

- [ ] 对现有独立Sage配置作最小差异：保留127.0.0.1:8443，新增IPv4 TCP443；域名只接受sagegogo.com。不开IPv6监听、80、www、CDN或其他入口；需要增加时作为明确新差异确认。此期必须使用完整https://链接，HTTP不做可用/重定向承诺。
- [ ] 安全组准备“准确出口IPv4 /32 → TCP443 → 允许”，优先级高于现有拒绝；保留其他全部拒绝及IPv6拒绝。检查所有关联安全组的实际合并/匹配效果，不假定新规则一定优先。绝不使用0.0.0.0/0、整段代理CIDR或“ALL允许”。
- [ ] Nginx再限定相同/32和回环诊断来源，其他deny all；审查所有location/内部跳转的继承规则，不能让health、错误页或新location绕过访问控制。默认公网/admin/和/sales/不开放，内部管理沿用TAT/回环。
- [ ] 经用户确认后配置独立入口HTTP Basic Authentication，并验证satisfy all，要求IP与口令同时满足而不是满足其一。用户在安全入口亲自输入、确认及保存新凭据，代理不读取明文或密码散列；核对现有Nginx模块及密码工具，不未经批准安装依赖。散列文件在站点根之外，权限仅root和实际Nginx工作用户可读；禁止明文/无盐SHA1。公网静态、API及health不得绕过入口认证；回环诊断若要豁免，只能是精确回环限定的入口。
- [ ] 若公网与回环采用不同入口认证要求，在同一独立配置内明确分为两个server监听作用域并核对有效配置；回环豁免不能继承到公网server。不能为了回环验收方便使用satisfy any让白名单IP绕过公网口令。
- [ ] Gunicorn保持127.0.0.1:8000，PG只用Unix socket；Nginx覆盖X-Real-IP和X-Forwarded-Proto，清除其他外部代理头。只信任精确127.0.0.1代理，不信任客户端提供的X-Forwarded-For；核验backend.http.client_ip实际行为，禁止放宽TRUSTED_PROXY_IPS通配范围。
- [ ] 入口认证通过后清除发往Gunicorn的入口Authorization头，不记录/转发口令或散列。现有Sage账户使用session cookie，不能把网关口令当应用账户；后续若有必须使用Authorization的供应商协议，另行设计，不盲清业务协议或放开整站。
- [ ] 443默认authority和原8443有区别：回读Host、Origin、Cookie、CSRF和Google回调，不照搬带:8443的配置。真实Google未获准前保持关闭；启用时才核对精确HTTPS回调。
- [ ] DEBUG=false、ALLOWED_HOSTS非通配、Secure/HttpOnly/SameSite、no-store、上传大小/非执行媒体、Host拒绝和HTTPS识别逐项验证。错误页不能暴露栈/配置；静态根只指向dist，.env、.git、源码、备份、媒体目录不直接提供。
- [ ] 保持注册/邮件/CAPTCHA/Google/SMS/账号实际删除/真实付款/自动续费/真实任务关闭。readonly目录/页面不等于已启售；真实预约提交也是业务写入，初期不开放。
- [ ] 日志不记查询串、OTP、OAuth code/state、Cookie、Authorization、密码、邮件地址或请求体。Nginx错误日志仍可能携带原始URI，必须单独验证；未解决不得启用真实OAuth，不关闭错误日志掩盖问题。
- [ ] 以准确独立配置路径运行nginx -t，核对完整有效配置和全部listen；日志留在受限证据目录。systemd兼容性、权限、原默认Nginx未启动/未变再次确认。预检0 Error不表示Warning可忽略：真实邮件关闭等属于范围，安全Warning逐项解释或修复。

**完成标准：**完整差异可以审阅；没有未解释的额外监听、授权、未知日志泄漏或依赖。此阶段不向公网放行。

### G5：最小放行与云端浏览器验收

- [ ] 批次开始前提交：ICP通过证据、实例/安全组、候选与配置摘要、准确/32、TCP443、入口认证、apex DNS变更、窗口、允许匿名会话产生的范围及关闭步骤。用户在实际操作前确认该精确批次并完成入口凭据交接；这不是全网/商业开放授权。
- [ ] 保持安全组拒绝时，安装并检查获准Nginx配置，重载既有独立Sage进程；确认443、回环8443/8000和PG状态准确。默认nginx.service仍不启动；配置失败立即恢复原配置。
- [ ] ICP已满足后，按保存的DNS差异设置apex A到已核实BoBo IPv4；保留邮件记录，不新增AAAA/www。先评估并处理已有冲突记录，不能盲删；TTL按实际值记录，DNS恢复不是即时隔离措施。
- [ ] 插入获准/32的443允许规则并回读其位置、其余拒绝和关联范围。立即从新的TAT连接复验管理，失败先关新入口，不以开放22救急。
- [ ] 从批准来源使用系统CA访问真实https://sagegogo.com，验证SNI/证书、无重定向循环、live/ready、首页与资源字节/摘要一致。初步HTTP检查不调用auth/session，不创建业务数据。
- [ ] 允许来源无入口凭证或口令错误时应拒绝，正确口令才可进入。共享出口下来源地址相同但没有凭证的访问也必须失败；测试过程中由用户输入凭据，不在curl命令行、Shell历史或截图中暴露Authorization。
- [ ] 从独立、已授权且实际出口不同的网络验证443被阻断，确认请求未到应用；手机若仍走同一代理不能算独立负向来源。没有独立负向来源则该门禁未完成，不用服务器内curl或伪造请求头代替。
- [ ] 针对目标实例复验22、80、8000、8443、5432公网不可达，IPv6无额外暴露；区分网络超时、云侧拒绝和HTTP拒绝，不把本机代理拒绝冒充安全组证据。不做其他目标或全网扫描。
- [ ] 进行下表安全矩阵；之后才用正常浏览器检查中英、移动宽度、200%浏览器缩放和键盘。浏览器执行auth/session产生的匿名测试会话作为已批准最小写入记录，不声称零DB变化；不抓取/展示Cookie值。
- [ ] 撤销此/32允许后，确认同一Mac新连接不能访问；终止已有公网连接/独立Nginx进程并确认停止，再新建TAT验证仍可管理。先核实云安全组对存量连接的行为，不假定删规则就一定断开所有旧连接。恢复精确允许也须属于已批准演练范围。

**完成标准：**正向、独立负向、私有端口和撤销四类证据均齐；只记录“指定来源公网受控内测通过”，不写“正式上线完成”。

## 5. 验收矩阵

G5执行网络、网关、匿名会话和关闭门禁检查；依赖真实账户/供应商的项在G6执行。G5通过不代表G6通过，缺账户材料时不能用fixture冒充云端跨账户测试。

| 检查 | 正向/反例 | 通过标准 |
|---|---|---|
| 访问来源 | 准确/32与独立非白名单来源 | 仅准确来源可达；缺独立来源不算通过 |
| 入口身份 | 允许来源无/错误/正确口令；共享出口其他访问 | IP和认证同时满足，入口凭据不传到应用或日志 |
| 服务边界 | 公网443、22/80/8000/8443/5432及IPv6 | 只有批准来源443可用，无旁路 |
| TLS/域名 | 实际CA校验、真实SNI、错误Host | 有效证书、TLS1.2/1.3、错误Host不能进应用 |
| 代理身份 | 伪造X-Real-IP/X-Forwarded-For/Proto | 覆盖/忽略伪造值；HTTPS和来源身份正确 |
| 会话/CSRF | G5匿名会话与Origin/token；G6登录会话/撤销 | 无敏感值输出；错误请求拒绝，不能只用CSRF cookie替代sessionid验收 |
| 资源 | 候选清单内资源和中英链接 | 字节一致，无缺资源、JS错误或串版本 |
| 私有路径 | G5私有文件/未登录头像；G6其他用户头像 | 不可读取；鉴权API不能跨账户 |
| 关闭门禁 | 注册、发信、Google、SMS、删除、交易、任务、预约写 | 不发供应商API请求、不收费、不假成功 |
| UI | 手机/桌面、中英、真实200%浏览器缩放、键盘 | 布局可用、焦点可达；文字放大不冒充浏览器缩放 |
| 日志 | 正常/错误/拒绝及回调路径 | 足够定位问题，无凭据/查询串泄漏 |
| 撤销 | 白名单删除、旧连接终止及新连接 | 外网访问失效，TAT管理保持可用 |
| 数据变更 | HTTP前后计数；批准浏览器会话写入 | 无意外用户/订单/任务/资金记录；不自动清理未知归属记录 |

## 6. 故障回退顺序

1. **先隔离**：撤销新增公网443允许；若规则通道不可用，停止独立Sage Nginx并确认443不再监听。终止既有公网连接，实测新连接不能访问；TAT保持可用。绝不改回ALL允许。
2. **再止损**：关闭获准期间启用的高风险业务入口和外部发送/调度；保留错误现场，不盲重发、不重复交易。
3. **再恢复配置/版本**：恢复批准备份的Nginx/服务配置和旧current；校验原安全属性、语法及回环健康。旧schema兼容未证明时不自动降代码。
4. **数据单独处理**：不清库、不自动逆迁移；如需恢复，先在不同获准库恢复/核对，再人工确认切换。真实停权、注销、资金事实不能被旧备份盲目“复活”或覆盖。
5. **最后处理DNS**：按保存的原记录恢复必要DNS；DNS有缓存，不能用DNS回滚代替第一步隔离。邮件MX/TXT不动。
6. **独立复验**：公网不可达、回环可用、PG仍无TCP监听、新TAT成功，报告具体失败点和保留现场；没有新证据不再连续叠加配置补丁。
